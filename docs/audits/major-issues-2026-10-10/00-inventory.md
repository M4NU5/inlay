### Duplicate implementations reviewers must keep in mind

- Two servers implement one contract: packaged TypeScript (`Server/src/`) and Swift reference (`Sources/InlayServerKit/`). The architecture doc names the Swift one a reference retained for comparison (`docs/architecture.md:14`), yet `Package.swift:6` still ships it as the `inlay-server` executable product and CI compiles all Swift packages (`.github/workflows/server.yml` swift job). Any behavioral claim must state which server it was verified in.
- Two copies of the text pipeline: `Server/src/domain/` (live on the packaged server) and `Sources/InlayDomain/` (used by the Swift reference server and linked into the client via `InlayCore`, `Package.swift:24`). File pairs: `dictionary.ts`↔`PersonalDictionary.swift`, `lists.ts`↔`SpokenListFormatter.swift`, `correction.ts`↔`TextCorrectionPolicy.swift`+`TextCorrectionAlignment.swift`, `composition.ts`↔`DictationComposition.swift`, `cleaner.ts`↔`TranscriptCleaner.swift`.
- Two Qwen helpers, one protocol: MLX Swift (`TextEngine/Sources/InlayTextEngine/`) vs llama.cpp C++ (`TextEngine/worker.cpp`). Bounds are documented once in `TextEngine/README.md` "Bounds and lifecycle" — check both implementations against it.
- Wire types exist three times from one source: `Server/api/openapi.yaml` (1,254 lines, OpenAPI 3.1, API version `2.0.0` at `Server/api/openapi.yaml:5`) generates `Server/src/generated/api.ts` and `Sources/InlayAPIWire/*`; `Sources/InlayAPI/API.swift` and `Server/src/api.ts` are hand-written facades on top. Version constants must agree: Swift `InlayAPI.version = 2` (`Sources/InlayAPI/API.swift:5`), TypeScript `API_VERSION = 2` (`Server/src/api.ts:73`), default port 8391 in both (`Sources/InlayAPI/API.swift:6`, `Server/src/api.ts:74`).

## Key user flows

### 1. Dictation (record → transcribe → proofread → deliver) — the core loop

1. Hotkey: hold Right Option / Right Control / Fn-Globe (`Sources/Inlay/System/HotkeyMonitor.swift:4`) in hold or double-tap-toggle mode (`Sources/Inlay/System/HotkeyMonitor.swift:83`). `HotkeyMonitor.start()` installs the event tap (`Sources/Inlay/System/HotkeyMonitor.swift:257`); Escape/mouse-down/permission-loss paths cancel or block the hold (`Sources/Inlay/System/HotkeyMonitor.swift:334`).
2. Admission before capture: `beginDictation` refuses to record unless the server is ready **and** API-version-matched (`isServerReady`, `Sources/Inlay/InlayController.swift:151`), mic permission is granted, and a microphone resolves (`Sources/Inlay/InlayController.swift:853`). It then creates the generation on the server (`connection.create`, `Sources/Inlay/InlayController.swift:894`) — the server checks speech readiness, disk space, idempotency by `(requestID, device.id)`, and freezes the preferences snapshot before any audio exists (`Server/src/generation-service.ts:412`).
3. Destination capture races recording start: for non-test takes the client begins Accessibility destination capture immediately (`TextInserter.beginDestinationCapture`, called at `Sources/Inlay/InlayController.swift:874`) while the mic starts independently; Electron targets may take up to ~3 s to become verifiable (`README.md:87`, logic in `Sources/Inlay/System/InsertionPreparation.swift` and `Sources/Inlay/System/TextInserter.swift:392`).
4. Streaming upload while speaking: `AudioRecorder` produces normalized 16 kHz mono float32 chunks (plus optional original-rate audio) into `AudioChunkPipe`; `ServerClient.upload` sends acknowledged, sequenced ≤1 MiB binary chunks per kind (`Sources/Inlay/ServerClient.swift:356`, route at `Server/src/http-server.ts:143`). Server enforces per-kind sequence/format, idempotent exact repeats, gap/conflict rejection (`docs/client-server-contract.md:17`, implementation `Server/src/generation-service.ts:482`).
5. Release/finish: `finishDictation` (`Sources/Inlay/InlayController.swift:938`) stops capture (takes <0.25 s are cancelled client-side, `Sources/Inlay/InlayController.swift:947`), drains uploads, then `POST /finish` with exact frame counts and optional continuation ID. Server verifies both intervals match (0.25–180 s), seals WAVs atomically, and queues FIFO processing (`Server/src/generation-service.ts:630`, `Server/src/generation-service.ts:696`). The mic is free for the next take while earlier takes finish — uploads are independent, inference is serial (`docs/architecture.md:28`).
6. Processing (one job at a time): Parakeet transcribe → mechanical cleanup → dictionary apply → spoken-list formatting → optional Qwen proofread → dictionary re-apply + deterministic rewrite guards in a worker → composition into `insertionText`/`previewText`/continuation (`Server/src/generation-service.ts:1031`, pipeline calls at `:1066`–`:1125`). Proofread rejection/failure keeps pre-proofreading text (`docs/architecture.md:30`, `proofread` fallbacks at `Server/src/generation-service.ts:1142`).
7. Progress + result: client holds `GET /v1/generations/:id/events` NDJSON (full `GenerationRecord` per line, 2 s heartbeats; `Server/src/http-server.ts:191`, `Server/src/generation-service.ts:747`) and can recover a dropped stream by re-fetching the generation (`Sources/Inlay/ServerClient.swift:286`). Completed uploads finish server-side even if the client disconnects; partial uploads expire; there is no offline queue or upload retry (`docs/architecture.md:34`).
8. Delivery: serialized per pending take in `deliver` (`Sources/Inlay/InlayController.swift:1093`) — see flow 2. Outcome is reported back separately from inference via `POST /delivery` (`Server/src/http-server.ts:181`). Test-microphone mode (`GenerationMode.test`) shows the transcript in-app and never inserts (`README.md:25`, mode chosen at `Sources/Inlay/InlayController.swift:895`).

Limits that shape this flow: 180 s max take (`Server/src/api.ts:75`, client timer in `Sources/Inlay/InlayController.swift:1315`), 1 MiB chunks (`Server/src/api.ts:76`), correction input cap 6,000 graphemes (`Server/src/domain/correction.ts:5`), helper deadlines (speech 180 s / proof 18 s at the server layer, `Server/src/inference/native-inference.ts:49`; 15 s inside the Linux text helper, `TextEngine/worker.cpp:25`).

### 2. Insertion (getting text into the user's app safely)

- Only `insertionText` may be inserted; `previewText` can include earlier list items and is display-only (`docs/architecture.md:38`). Continuation (appending to a previous take's list/paragraph) requires a same-device prior generation **and** a confirmed client caret anchor; the server re-checks age/delivery state and silently falls back to standalone (`docs/architecture.md:38`, server check `Server/src/generation-service.ts:995`, client anchor memory `Sources/Inlay/InlayController.swift:1175`).
- At delivery time the Mac re-validates everything: focused app/field identity, selection, protected/password fields, modifiers, clipboard change count (`TextInserter.deliver`, `Sources/Inlay/System/TextInserter.swift:198`; field eligibility policy `Sources/Inlay/System/TextInserter.swift:101`; caret policy `:127`). Strategies: direct AX value replacement vs synthesized Cmd-V paste (`deliveryStrategy`, `Sources/Inlay/System/TextInserter.swift:565`; `Sources/Inlay/System/NativePasteCommand.swift`), wrapped in `TextDeliveryTransaction` with clipboard save/restore (`DictationClipboard`, `Sources/Inlay/System/TextInserter.swift:629`). Unsafe or unverifiable destinations degrade to clipboard-copy or in-app preview, never blind typing (`docs/architecture.md:40`).
- Only a **confirmed** insertion advances continuation anchors (`rememberContinuation`, `Sources/Inlay/InlayController.swift:1187`); overlapping confirmed inserts rebase later pending destinations (`Sources/Inlay/System/ConfirmedInsertionRebases.swift`, applied at `Sources/Inlay/InlayController.swift:1153`). Editor text and AX handles never leave the Mac (`docs/architecture.md:40`) — the wire carries only a continuation generation ID (`docs/client-server-contract.md:40`).
- Reviewer hotspots: `TextInserter.swift` (718 lines, heavy off-main AX probing), `TextDeliveryTransaction.swift`, `InsertionPreparation.swift` (Electron AX-tree activation, with the documented cost that the target app keeps its AX tree enabled for its lifetime, `README.md:87`).

### 3. History (shared, server-owned)

- All connected Macs read the same paginated history, tagged by originating device (`docs/architecture.md:74`). Client: `HistoryPage` (`Sources/Inlay/Views/HistoryPage.swift`) over `refreshHistory`/`loadMoreHistory` with cursor + source filter (`Sources/Inlay/InlayController.swift:340`, filter `source=inlay` is the API-v2 native filter, `docs/client-server-contract.md:5`). Server: `GET /v1/generations?limit&before&source` (`Server/src/http-server.ts:128`, `Server/src/generation-service.ts:710`).
- Per-record actions: play/download audio, open imported artifacts, delete (`deleteGeneration` `Sources/Inlay/InlayController.swift:664`, `openGenerationAudio` `:675`; server `DELETE` refuses active generations, `Server/src/generation-service.ts:856`; artifact allowlist serving `Server/src/generation-service.ts:871`, route `Server/src/http-server.ts:204`). Opening history never pastes an old result (`docs/architecture.md:34`).
- On disk: `--data-dir` holds `preferences.json` + `generations/<UUID>/{metadata.json, transcript.txt, inference.wav, original.wav}` (`docs/architecture.md:64`). Inference audio is always kept for completed takes; original audio defaults on and the toggle affects only future takes; nothing auto-expires (`docs/architecture.md:70`). Restart marks unfinished generations failed and keeps completed history (`docs/architecture.md:34`, startup reconciliation in `GenerationService.initialize`, `Server/src/generation-service.ts:209`).

### 4. Preferences (two scopes, one window)

- Window pages: Dictation / History / Microphone / Server preferences / This Mac (`InlayPage`, `Sources/Inlay/Views/InlayWindowView.swift:4`; routing `:69`). Server-preferences and device pages live in `Sources/Inlay/Views/PreferencesPage.swift`; mic selection/test in `Sources/Inlay/Views/MicrophonePage.swift` (562 lines).
- This Mac edits write `config.json` through `ConfigurationStore` (watched file, last-good-on-invalid, `Sources/Inlay/ConfigurationStore.swift:8`) and `client.json`/Keychain via `ClientPreferencesStore` (`Sources/Inlay/ClientPreferences.swift`); connection changes go through `saveConnection` (`Sources/Inlay/InlayController.swift:324`) and `ServerEndpoint` validation before credentials load (`Sources/Inlay/ServerEndpoint.swift:4`).
- Server preferences save with optimistic concurrency: client sends expected revision, server 409s stale writes (`updateSharedPreferences` `Sources/Inlay/InlayController.swift:648`; `Server/src/generation-service.ts:387`; contract `docs/client-server-contract.md:46`). Validation limits (prompt ≤4,096 bytes, vocabulary ≤16 KiB, ≤32 dictionary lists/500 terms/8 aliases) are enforced server-side (`docs/client-server-contract.md:48`, `preferencesValidationError` `Server/src/generation-service.ts:90`) and mirrored in Swift (`Sources/InlayAPI/API.swift:75`).
- Microphone flow: priority-ordered device resolution (`Sources/InlayCore/MicrophonePreferences.swift`, live store `Sources/Inlay/System/MicrophonePreferencesStore.swift`, hardware enumeration `Sources/Inlay/System/AudioDeviceStore.swift`); route changes apply to the next take, and sleep/lock/device-loss ends capture (`docs/architecture.md:42`, interruption handling `Sources/Inlay/System/AudioRecorder.swift:190`). Optional mute-system-output-while-recording restores only what Inlay changed; a crash mid-take can leave output muted (`docs/architecture.md:44`, `Sources/Inlay/System/SystemOutputMuter.swift`).

### 5. Onboarding / permissions / first run

- There is no separate onboarding wizard: first launch (or missing permission, or config error) opens the main window (`Sources/Inlay/InlayApp.swift:67`), where Dictation page + `PermissionHelpView` (`Sources/Inlay/Views/PermissionHelpView.swift`) guide grants. Three TCC permissions matter: Microphone, Accessibility (insertion + event listening), Input Monitoring (only needed without Accessibility) — snapshot logic `Sources/Inlay/System/Permissions.swift:7`, requests/deep-links `:24`; controller refresh/request surface `Sources/Inlay/InlayController.swift:1241`. `allPermissionsGranted` = mic + accessibility (`Sources/Inlay/InlayController.swift:154`).
- First-run server setup is manual: user must have a server running (same-Mac `run-dev.sh` or remote per `Server/README.md`), then enter URL + token under This Mac (`README.md:21`). Health distinguishes reachable vs inference-ready (`GET /v1/health` → `ServerHealth` with per-model `ready`, `Sources/InlayAPI/API.swift:115`; server `health()` `Server/src/generation-service.ts:337`); the client blocks dictation until `ready && apiVersion == 2` (`Sources/Inlay/InlayController.swift:151`).
- Identity traps for reviewers: Release (`dev.davis.inlay`) vs Dev (`dev.davis.inlay.dev`) have separate data dirs, Keychain services, and TCC grants (`Sources/InlayCore/InlayBuild.swift:11`, plists in `Resources/`); ad-hoc-signed rebuilds can force re-granting permissions (`README.md:83`). Signing picks the sole Apple Development identity if exactly one exists, else ad-hoc (`scripts/build-app.sh:44`).
- Wispr Flow import (migration path, reachable from the app): client reads Wispr Flow's local SQLite/artifacts read-only (`WisprFlowSourceReader`, `Sources/Inlay/WisprFlowSourceReader.swift:70`; discovery `:131`), previews, then stages each session through `/v1/imports/wispr-flow*` with checksummed artifact manifests and atomic publish (`Server/src/http-server.ts:223`, `Server/src/imports.ts`); dictionary archive is preserved but does not change the active dictionary (`docs/client-server-contract.md:28`). ## Data flow: client ↔ server ↔ engines

```text
┌─ Mac client (Sources/Inlay) ──────────────────────────────────────────┐
│ HotkeyMonitor ─► InlayController ─► AudioRecorder (CoreAudio input)   │
│                       │  ▲                      │ PCM chunks          │
│              TextInserter (AX)           AudioChunkPipe               │
│                       ▲                      │                        │
│                       └──── ServerClient (URLSession) ────────────────┼──┐
└───────────────────────────────────────────────────────────────────────┘  │ HTTP /v1, Bearer token
┌─ Server (Server/src, Fastify on Bun) ─────────────────────────────────┐  │
│ http-server ─► GenerationService ─► storage (data-dir generations/)   │◄─┘
│                     │ serial FIFO queue                               │
│                     ├─► NativeInference ─► HelperProcess ──stdin/out──┼─► inlay-engine (Parakeet+Silero, WAV path in JSON)
│                     │                   └─► HelperProcess ──stdin/out──┼─► inlay-text-engine (Qwen MLX or llama.cpp)
│                     └─► domain/* (clean→dictionary→lists→guards→compose; guards in correction Worker)
└────────────────────────────────────────────────────────────────────────┘
```

- Wire contract: single source `Server/api/openapi.yaml`; 20 routes tabulated in `docs/client-server-contract.md:9` and implemented at `Server/src/http-server.ts:119`. Auth/transport guards run as an `onRequest` hook: tokenless ⇒ Host must be loopback (`Server/src/http-server.ts:73`); with token ⇒ `Authorization: Bearer` compared timing-safely, health exempt (`Server/src/http-server.ts:80`); any `Origin` header is rejected — browser access is deliberately impossible (`Server/src/http-server.ts:87`, `docs/development.md:24`). Default JSON body limit 256 KiB (`Server/src/http-server.ts:60`) with per-route binary limits (1 MiB audio chunks, 8 MiB import artifacts/dictionary).
- Audio path data: inference = mono 16 kHz float32 LE; original = mic-native rate/channels float32, uploaded/kept only when the admission snapshot says `keepOriginalAudio` (`docs/client-server-contract.md:36`, client gate `Sources/Inlay/InlayController.swift:917`). Server seals both as WAV (`seal`, `Server/src/generation-service.ts:928`) and hands the speech helper a **file path**, not bytes (`transcribe(join(directory, "inference.wav")…)`, `Server/src/generation-service.ts:1053`; helper request shape `Engine/README.md:9`).
- Helper protocols: bounded newline-delimited JSON over pipes, one outstanding request per helper, models loaded once and kept warm, `ready` handshake, progress events for speech (`Engine/README.md:18`), request bounds speech 1 MiB (`Engine/worker.cpp:51`) / proof 64 KiB (`TextEngine/worker.cpp:22`). Server-side supervision (spawn, line limits, timeouts, restart-on-hang, stderr drain without storing transcripts) is `HelperProcess` (`Server/src/inference/helper-process.ts:79`) configured from `NativeInference` (`Server/src/inference/native-inference.ts:163`). Helpers self-terminate on parent death (Linux `PR_SET_PDEATHSIG`, `Engine/worker.cpp:76`; `TextEngine` equivalents + Swift `ParentWatcher` in `TextEngine/Sources/InlayTextEngine/Protocol.swift`). Cancellation of active inference = terminate helper process (`TextEngine/README.md:24`).
- Text path data: raw Parakeet text → `cleanTranscript` → `applyDictionary` → `formatSpokenList` → (optional) Qwen with snapshotted prompt + ≤80 dictionary hint terms → `applyDictionary` again → deterministic guards (`evaluateCorrectionInWorker`, alignment/number/negation checks in `Server/src/domain/correction.ts`) → `composeDictation` splits `insertionText` vs `previewText` + continuation state. Every stage's provenance (model IDs, SHA-256s, backends, timings, hint usage, rejection reasons) is persisted on the record (`Server/src/generation-service.ts:1070`) — history UI surfaces it, so reviewers can audit quality decisions from `metadata.json`.
- Model trust: server verifies pinned model files before load and never downloads weights (`Server/src/inference/model-verification.ts`; pins `Server/src/inference/model-pins.ts`; Swift manifests `Sources/InlayCore/SpeechModel.swift`, `Sources/InlayCore/TextModel.swift` — note pins exist in **both** languages plus `scripts/download-model.sh`). Readiness ≠ process-alive: `health` reports per-model verified+loaded state (`Server/src/inference/native-inference.ts:188`), and admission fails 503 with warmup kicked off when speech isn't available (`Server/src/generation-service.ts:437`).
- Durability/concurrency model: single-writer data directory enforced by lock file (`Server/src/main.ts:8`, `Server/src/data-lock.ts`); all mutations serialized through `GenerationService.mutate` promise chain (`Server/src/generation-service.ts:196`); writes are temp-file + fsync + rename + directory fsync at mode 0600/0700 with symlink refusal (`Server/src/storage.ts:47`); ≥100 MiB free required before accepting audio (`Server/src/storage.ts:94`). No database — the filesystem under `--data-dir` is the store; in-memory `records`/`uploads` maps are rebuilt at startup (`Server/src/generation-service.ts:209`).
- What never crosses the wire: editor contents, AX handles, caret positions (only an opaque continuation generation ID), Keychain tokens beyond the Bearer header, and browser traffic of any kind. What always crosses: full audio (both kinds when enabled) and full transcripts — the server data dir must be protected like the recordings it contains; no at-rest encryption is added (`docs/architecture.md:76`).

## Build and release paths

### Daily development (two different servers — do not confuse them)

- Source server (hot reload): `bun install --frozen-lockfile` then `bun run dev` → `Server/scripts/dev.ts` binds `0.0.0.0:8392`, isolates data in `.local/dev-server/data`, creates/reuses a private token file, and forces `INLAY_DEV=1` (`Server/scripts/dev.ts:25`, root script `package.json:9`). Starts fine without helpers/models; health then reports `ready: false` (`docs/development.md:17`).
- Packaged dev pair: `./scripts/run-dev.sh` builds/starts the **packaged** server on port 8391 with archive `.local/server`, client prefs `.local/client`, PID/log under `.local/` (`scripts/run-dev.sh:9`), and launches `build/Inlay Dev.app` with `INLAY_CLIENT_DATA_DIR` + `INLAY_SERVER_URL` injected via `open --env` (`scripts/run-dev.sh:17`). Supports `start --skip-build` / `status` / `stop` / `restart` (`README.md:75`). Stale-PID safety: it verifies the PID's command line before signalling (`scripts/run-dev.sh:38`).
- Static gates (the only allowed automated checks): `bun run fmt` / `fmt:check` (Prettier), `bun run lint` (oxlint type-aware, warnings fail), `bun run check` (`tsc --noEmit` + generated-TypeScript consistency) — root `package.json:13`.
