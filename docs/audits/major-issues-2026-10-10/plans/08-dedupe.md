## Goal

- One server: the Swift reference server (`Package.swift:6`) and the Swift-only text-pipeline logic that exists solely to serve it are deleted; the Bun/TypeScript server is the only `inlay-server`.
- One source per shared fact: API version/port/limits, the supported-language list, the default proofreading prompt, and the model pins are generated into TypeScript and Swift from a single source each, and a deterministic parity check inside `bun run check` fails when a non-generated copy (shell script) disagrees.
- The Wispr Flow import driver (~265 lines inside `InlayController`) is isolated as its own type, so the migration bridge can later be deleted by removing a small named set of files instead of surgery on the god-controller.
- The double-decode wire facade (`Sources/InlayAPI/APIWire.swift:12`) is retired type-by-type for the plain types where it is provably safe, with an explicit defer list (with reasons) for the rest — no big-bang rewrite.
- History list responses stop shipping full records: a summary projection replaces `GenerationPage.items` under an API version bump, and the detail view fetches the full record on selection through the existing single-record route.
- Success is judged per slice by `bun run check` / `bun run lint` / `swift build` plus the Inlay Dev manual steps in Verification. No behavioral automated tests anywhere (`AGENTS.md:4` ban stays); the only new automated check is the deterministic parity check DECISIONS explicitly allows (`DECISIONS.md:21`).

## Risks

- **Restack drift (highest risk)**. Every `file:line` here is at `b6d6815`; Batches 1–7 rewrite `InlayController.swift`, `generation-service.ts`, `openapi.yaml`, and `HistoryPage.swift` before this branch starts. Mitigation: each slice's pre-flight is a symbol search, not a line jump; Slice 1/2 caller searches and Slice 7's per-type pre-flight must be re-run and their results pasted into commit messages. If an earlier batch already did part of a slice (e.g. Batch 4 extracted something from `generation-service.ts`), shrink the slice — never re-implement.
- **Batch 5 version arithmetic**. Slice 6 assumes Batch 5 landed its 2 → 3 bump (`plans/05-trust-data.md:100`). If Batch 5 changed its mechanics (or Batch 4's optional fields at `plans/04-server-throughput.md:108` didn't land), Slice 6's "current + 1" and summary field set must be recomputed from the restacked `openapi.yaml`, not copied from this plan. The Slice 3 generator is what makes that recomputation cheap; the risk is skipping the check.
- **Slice 3 transcription errors fail silently without runtime tests**. A typo'd SHA in `model-pins.json` makes the server reject a good model (fail-closed, visible as `ready: false`) — safe direction, but only if someone runs the Inlay Dev dictation step. A typo'd _prompt_ byte changes proofreading output with no error at all. Mitigations: first generation must reproduce today's `macProofManifestSHA256` from computation (a self-check that the Qwen transcription is right), `--print-default-proofreading-prompt` diff before/after, and the Verification section's real-dictation step is mandatory for Slice 3, not optional.
- **Generator determinism across machines**. Slice 3's Swift emitter must produce byte-identical output on the author's Mac and in CI or `generate:api --check` flaps. Mitigation: sort all generated collections explicitly, LF-only line endings, no locale-dependent formatting, integers emitted without grouping separators except where Swift style already uses them (match by construction, not by post-formatting — there is no Swift formatter in the gate).
- **`Package.resolved` pruning surprises (Slice 1)**. Removing hummingbird/swift-crypto changes the resolved graph for every consumer, including `TextEngine` (its own `Package.resolved` pins the root package by path — `TextEngine/Package.swift:9`). Mitigation: Slice 1's verification includes building `TextEngine`'s package resolution (`swift package --package-path TextEngine resolve`) and the helper compile in Verification; if resolution wants to _upgrade_ unrelated pins, stop and pin instead of accepting a lockfile-wide churn.
- **Slice 6 detail-fetch race**. Summary list + on-demand detail introduces a stale-selection window that today's single-fetch design cannot have. Mitigation is the endpoint+revision guard copied from `refreshHistory:340`; the manual step (rapidly clicking through history on a slow/remote server) is in Verification because no static gate can see it.
- **Slice 7 optional-encoding edge**. The omit-nulls contract makes generated encoding equivalent _for fields that are optional in the schema_. If any 7a/7b type has a field that is optional in the facade but required (or vice versa) in `openapi.yaml`, conversion changes what's on the wire. The per-type pre-flight compares facade stored properties against the schema block field-by-field; any mismatch triggers the stop rule.
- **Deleting something the owner still consults**. DECISIONS `:18` settles the Swift server, but Slice 1–2 are the stack's only irreversible-feeling deletions (~3,400 lines total). They are of course recoverable from git history (`audit/major-issues` @ `b6d6815` and earlier); the Slice 1 commit message names that recovery point so a future "what did the Swift version do?" question has an answer that isn't a live target.
