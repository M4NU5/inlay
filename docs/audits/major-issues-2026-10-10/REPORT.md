## Top finding — read this first

**Speech you have already recorded, uploaded, or sealed can still be silently destroyed — and the system already holds everything needed to save it.**

- [ServerClient.swift:382](/Users/davis/Developer/inlay/.local/worktrees/major-issues-audit/Sources/Inlay/ServerClient.swift:382) — one failed chunk upload fails the whole session (cancelServer) with no retry, even though the server re-acknowledges exact chunk replays (`Server/src/generation-service.ts:551`) and the full take sits in a local WAV that is deleted, never resent.
- The same total loss fires on a transient 5-second health-poll failure mid-recording (`Sources/Inlay/InlayController.swift:319`), on sleep/lock/device-loss (`Sources/Inlay/InlayController.swift:1229`), on server restart destroying sealed queued takes (`Server/src/generation-service.ts:315`, `:272`), and on a 45-second receiving expiry during slow-uplink drain (`Server/src/generation-service.ts:307`).
- Individually each path is P1 (it needs an interruption trigger). Together they mean every stage of the core loop — capture, upload, queue, delivery — is all-or-nothing. Three independent auditors found this cluster (`01 F3 = 07 F1 = 10 F1` plus subsets), and it survived hostile re-reading intact (`11-crosscheck.md:12`). Fix it first; most of the machinery (idempotent replay, retry-safe `finish`, local capture file) already exists and is unused for audio.
- The only formal P0 is next: VoiceOver users get no dictation outcome at all (`Sources/Inlay/InlayApp.swift:273`). It is narrower in audience than the cluster above, but for those users the product loop is fully closed.

## Executive summary

- Inlay's happy path is carefully built (admission checks, sequenced acknowledged chunks, atomic fsync storage, guarded insertion, proofread fallback). The major issues are almost all failure handling, feedback, and defaults — not happy-path correctness.
- **Data loss is the dominant theme.** A network blip, health-poll miss, sleep, unplugged mic, slow uplink, or server restart at the wrong second destroys up to 180 seconds of speech that was already durable somewhere. There is no retry, salvage, requeue, or relaunch reconciliation at any stage.
- **One bad file takes everything down.** A single corrupt/duplicate/future-version record bricks server startup with no named culprit (`Server/src/generation-service.ts:252`), and the server runs with logging effectively off (`Server/src/http-server.ts:60`), so field failures leave no trace to debug from.
- **Feedback fails where the safety design succeeds.** Insertion correctly refuses blind typing, but "copied" dismisses in 1.7 s like success (`Sources/Inlay/InlayController.swift:1038`), processing is an opaque spinner with no stage/queue (`Sources/Inlay/Views/MenuHUDViews.swift:219`), a failed hotkey press steals focus into the Inlay window (`Sources/Inlay/InlayController.swift:852`), and VoiceOver users are told nothing at all.
- **The server is slower and more fragile under concurrency than it needs to be.** One global mutation lock serializes per-chunk fsync, WAV sealing, history, and health (`Server/src/generation-service.ts:196`); one unbounded serial FIFO couples transcribe+proof+score (`Server/src/generation-service.ts:1014`); any routine helper error kills the warm model (`Server/src/inference/helper-process.ts:300`).
- **Trust defaults are wide open on the default setup.** The same-Mac server is unauthenticated to any local process (`Server/src/http-server.ts:73`), one shared token is all-or-nothing with self-asserted device IDs (`Server/src/generation-service.ts:417`), and everything — both audios, raw text, settings snapshots, Wispr screenshots, post-seal cancelled takes — is kept forever in plaintext (`docs/architecture.md:70`).
- **First run and distribution don't exist yet as product flows.** A standalone app install dead-ends without shell/README server+model setup (`Sources/Inlay/ClientPreferences.swift:30`), there is no distributable/notarized Mac client (`scripts/build-app.sh:44`), and CI never exercises client packaging (`.github/workflows/server.yml:49`). Whether this is P1 or intended depends entirely on the distribution question (Q1 below).
- **Duplication is the top change-risk, not a current user bug.** Two servers, two text pipelines, triple wire types with a double-decode shim, and hand-copied constants/prompt/pins with no agreement check (`Package.swift:6`, `Sources/InlayAPI/APIWire.swift:12`, `Server/api/openapi.yaml:11`) — all confirmed as facts, regraded to P2 because values agree today. The `AGENTS.md:4` test ban removes the only scalable parity check, so drift will be found by a human dictating.
- **~42 P0/P1 headlines dedupe to ~28 unique issues** (`11-crosscheck.md:96`). The audit set is unusually accurate: 28 confirmed, 7 confirmed-but-overstated, 2 contradictory halves of one finding, 1 sub-claim + 1 P2 refuted outright. Do not build a backlog from the raw counts.
- Two routed areas were never actually audited — text-pipeline correctness (`Server/src/domain/*`) and insertion-safety logic end-to-end — so "no finding" there means "not looked", not "safe". See "What was not verified".

## Major issues

- **P0-1. VoiceOver users get no dictation outcome** — HUD lives in a non-activating, never-key panel with zero `NSAccessibility` announcements and zero sounds; results auto-dismiss in 1.7–4 s and the menu-bar icon reverts to idle after failure. ## Themes / patterns

- **All-or-nothing failure handling at every stage.** Capture, upload, seal, queue, processing, and delivery each discard durable work on transient failure, though idempotency primitives (chunk replay, retry-safe finish, local capture file, sealed WAVs) exist at every stage and go unused for recovery (P1-1/2/3/4, seal + expiry P2s).
- **Safety without feedback.** The client makes conservative decisions (refuse blind typing, guarded clipboard, focus-stealing error window) but communicates them weakly or destructively: icon-only HUD, 1.7 s dismissals, opaque spinner, silent settings failures (P0-1, P1-11/12/13/20).
- **Single points of serialization.** One mutation lock, one FIFO, one outstanding helper request, one delivery chain, one 5 s health poll with kill power — every subsystem queues behind exactly one thing, so stalls cascade (P1-4/8/9).
- **Defaults optimized for the owner's desk.** Tokenless loopback, HTTP-on-Tailscale-ranges, forever retention, personal hostname in the launcher, diagnostics as shipped UI — each is reasonable personal tooling and wrong as a shipped default (P1-15/17, 06/09 P2s). Q1 decides how much of this is a bug at all.
- **Duplication without a checker.** Every cross-boundary fact (servers, pipelines, wire types, constants, prompt, languages, pins, versions) lives 2–4 times; the only gates are typecheck/lint/compile, and `AGENTS.md:4` forbids the parity tests that would make duplication safe. Drift failure mode is outage, not subtlety (P2 architecture cluster).
- **Observability treated as a privacy risk, not a reliability tool.** Logging off + stderr discarded + in-memory-only diagnostics means none of the above can be frequency-graded from the field; every "how often?" in this audit is inferred (P1-6).
